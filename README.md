# 3D Print Lab — сайт для GitHub Pages

Статический русскоязычный сайт о 3D-печати с адаптивной версткой, 8 страницами, интерактивными возможностями и заготовками подключения счетчиков аналитики. Написан на HTML, CSS и JavaScript, без сборки и серверной части.

## Страницы

- `index.html` — главная
- `technologies.html` — FDM, SLA/MSLA, SLS
- `materials.html` — каталог PLA, PETG, ABS, TPU: фильтры и поиск
- `guides.html` — инструкция, чек-лист с возможностью скачивания
- `calculator.html` — калькулятор стоимости FDM-печати в рублях
- `quiz.html` — интерактивный тест по 3D-печати из 6 вопросов
- `about.html` — сведения о проекте и черновик обратной связи
- `privacy.html` — управление согласием на веб-аналитику

## Как запустить на компьютере

1. Разархивируйте весь сайт в одну папку.
2. Откройте `index.html` в браузере. Главная страница и основные функции работают без сервера. **Для проверки подгрузки счетчиков требуется локальный HTTP-сервер или опубликованный GitHub Pages**, поскольку `fetch()` в браузере может не работать с `file://`.
3. При наличии Python можете выполнить из папки проекта `python -m http.server 8000` и открыть `http://localhost:8000/` (это только для локального тестирования, на хостинге Python не нужен).

## Как опубликовать на GitHub Pages

1. Войдите в https://github.com и создайте новый **публичный** репозиторий, например `3d-print-lab`.
2. Загрузите содержимое папки `3d-print-lab` в корень репозитория. **Не загружайте сам ZIP как единственный файл**. Убедитесь, что `index.html` находится в корне репозитория.
3. Откройте **Settings → Pages → Build and deployment**.
4. Выберите **Deploy from a branch → main → /(root) → Save**.
5. После публикации откройте `https://ВАШ_ЛОГИН.github.io/3d-print-lab/`.
6. При изменении файлов GitHub Pages обновит сайт после публикации изменений.

> GitHub Pages публикует статические файлы. В проекте нет базы данных, регистрации, CMS или сервера. Кнопка «Подготовить текст» не отправляет сообщение, а копирует его в буфер обмена.

## Аналитика для ЛР № 3, 4 и 5

**Важно:** реальные счетчики ещё НЕ подключены. Ни у одного из трех сервисов нет выдуманного ID. Код счетчика берите только из своего кабинета после регистрации публичного адреса сайта, а не с сайтов с примерами чужих ID.

### Согласие посетителей

При первом посещении пользователь выбирает «Разрешить» или «Отклонить». Только после согласия сайт читает сниппеты счетчиков из `integrations/`. Решение сохраняется в localStorage браузера. Посетитель может изменить его через «Настройки аналитики» в подвале. После отмены согласия страница перезагрузится.

> Учитывайте, что пользователи, отказавшиеся от аналитики, не будут видны в сторонних счетчиках. Учитывайте это при планировании набора 50 пользователей. Для юридически значимой публикации проверьте местные требования к обработке данных и адаптируйте политику конфиденциальности под собственную ситуацию.

### Общий способ установки кода каждого счетчика

1. Откройте соответствующий файл `integrations/liveinternet.html`, `integrations/rambler.html` или `integrations/mytracker.html` в обычном текстовом редакторе.
2. Полностью удалите текст-заглушку.
3. В первую строку **добавьте точно** служебный HTML-комментарий:

```html
<!-- COUNTER_INSTALLED -->
```

4. Под ним целиком вставьте **официальный HTML/JS-код счетчика**, выданный сервисом (без изменений).
5. Сохраните в UTF-8, загрузите обновленный файл в GitHub, дождитесь обновления сайта.
6. На опубликованной странице дайте согласие, откройте DevTools → Network и проверьте внешние запросы к конкретному сервису. Не проверяйте только на `file://`.

Сниппеты подгружаются динамически **после согласия**, поэтому отдельные кабинеты могут требовать дополнительной настройки для корректной атрибуции самых коротких визитов. Проверяйте в Network и в разделе статуса установки счетчика. Если код использует `document.write`, замените его на современный асинхронный вариант из кабинета сервиса.

### ЛР № 3: LiveInternet

- Регистрация: https://www.liveinternet.ru/add
- Получение собственного кода и оформление видимого счетчика: https://www.liveinternet.ru/code
- Инструкция: https://www.liveinternet.ru/help/faq.html
- Для `integrations/liveinternet.html` используйте сгенерированный HTML-код. Он должен содержать **ваш** зарегистрированный адрес/счетчик.
- Ведите наблюдения по страницам, источникам переходов, устройствам, динамике и ключевым метрикам.

### ЛР № 4: Рамблер/Топ-100

- Помощь при создании: https://help.rambler.ru/top100/top100-faq/1540
- Установка/проверка: https://help.rambler.ru/top100/counter-settings/1566
- Параметры визитов через `sendCustomVars`: https://help.rambler.ru/top100/poleznye_materialy/1713/
- Сгенерированный код счетчика вставляется в `integrations/rambler.html`.
- В `assets/js/analytics.js` уже есть **проверенный вызов** `top100Counter.sendCustomVars({'3dprintlab::calculator_result': 1})` (и аналогично для остальных событий), если счетчик корректно инициализирован.
- Создайте в кабинете отчеты по параметрам визитов: например, `3dprintlab::calculator_result` и `3dprintlab::quiz_completed`; отчеты по фильтрам/скачиваниям — по необходимости.

### ЛР № 5: MyTracker — замена старого Рейтинга Mail.ru

- Веб-трекинг: https://docs.tracker.my.com/ru/tracking/web_tracking
- Подключение веб-счетчика/целей: https://docs.tracker.my.com/ru/sdk/web/api
- В своем кабинете MyTracker создайте приложение и веб-счетчик. Код вставьте в `integrations/mytracker.html`.
- В `integrations/mytracker-config.js` установите **публичный числовой ID** своего счётчика, например `window.__MYTRACKER_COUNTER_ID__ = 'ВАШ_ID';` (без секретных ключей!).
- После согласия и загрузки кода `assets/js/analytics.js` отправляет реальные пользовательские цели через официальную очередь `_tmr.push({id, type:'reachGoal', goal:'quiz_completed', params:{...}})`.
- Старый интерфейс Рейтинга Mail.ru может не соответствовать заданию: согласуйте с преподавателем допустимость MyTracker.

## События и цели (названия стабильны)

| Событие | Когда действительно отправляется | Пример применения |
|---|---|---|
| `hero_calculator_click` | Нажата кнопка калькулятора на главной | Интерес к инструменту |
| `material_filter` | Нажат фильтр каталога | Разделение по интересам |
| `material_search` | Введен поисковый запрос из 2+ символов | Вовлеченность |
| `calculator_result` | Успешно рассчитана стоимость | Цель 1 / конверсия |
| `quiz_started` | Открыт интерактивный тест | Начало воронки |
| `quiz_answer` | Выбран вариант ответа | Шаг воронки |
| `quiz_completed` | Пройдены все 6 вопросов | Цель 2 / конверсия |
| `quiz_restart` | Повторный запуск теста | Вовлечённость |
| `checklist_download` | Нажато скачивание памятки | Цель 3 |
| `contact_draft` | Сформирован текст вопроса | Интерес к обратной связи |
| `guide_print` | Нажата кнопка печати руководства | Полезное действие |

Метрики числа посетителей **не имитируются**. Перечисленные события возникают только по факту действий пользователя, и отправляются во внешние сервисы только после согласия и установки настоящих счётчиков.

Для проверки работы в браузере можно добавить к URL `?analytics_debug=1` (например, `/quiz.html?analytics_debug=1`) и открыть Console. Это **диагностические сообщения, а не подтверждение приема событий внешним сервисом**. Проверку получения нужно делать в статистике сервиса и на вкладке Network.

## Что подготовить для отчётов

1. Скриншот опубликованного сайта и минимум 5 разных страниц.
2. Регистрационные и настроечные экраны каждого счетчика + ваш официальный код/ID (секретные ключи не показывайте).
3. Скриншоты графиков посещений/устройств/источников, минимум за 1–2 недели.
4. Отдельные скриншоты целей и пользовательских отчетов: `calculator_result`, `quiz_completed`, `checklist_download`.
5. Статистику по реальным посетителям (в заданиях требуется не менее 50). Без генераторов посещений и вымышленных результатов.
6. Не менее 3 Word-отчетов для ЛР № 3, 4, 5 с собственной интерпретацией реальных данных, таблицами, рисунками и источниками.
